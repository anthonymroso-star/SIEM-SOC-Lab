# Incident Response Report: Brute-Force Attack Analysis (NIST SP 800-61 r2)  
  
## 1. Incident Summary  
* **Who:** An external malicious threat actor targeting administrative access privileges.  
* **What:** A high-velocity, automated SSH dictionary/brute-force attack.  
* **When:** Detected on 2026-07-08 between 22:25:00 and 22:30:00 UTC.  
* **Where:** Target asset server `**server` (Internal IP: `x.x.x.x`) running an open SSH daemon interface.  
* **Why:** To gain unauthorized shell access, compromise service persistence, or exfiltrate host data.  
  
## 2. Detection & Telemetry Analysis  
The attack vectors were captured in real-time by the active Wazuh agent monitoring `/var/log/auth.log`.  
  
### Key Telemetry Triggers:  
* **Wazuh Rule ID:** `5710` (sshd: Attempt to login using a non-existent user)  
* **MITRE ATT&CK Mapping:** T1110.001 (Brute Force: Password Guessing)  
* **Forensic Payload Signature:**  
```json  
"full_log": "Failed password for invalid user fakeuser from x.x.x.x port 58624 ssh2"  
```  
  
The event profile indicated high-frequency automated spraying, mapping out multiple invalid credentials (`fakeuser`, `fakeuser3`) within milliseconds.  
  
## 3. Containment & Remediation Actions  
To mitigate the threat vectors immediately, a three-phase playbook execution was carried out:  
  
1. **Host Isolation/Hardening:** Modified network daemon properties within `/etc/ssh/sshd_config` to explicitly restrict root credential negotiations across open port maps (`PermitRootLogin no`).  
2. **Telemetry Validation:** Restarted security engines to trigger immediate auditing routines. Telemetry feedback loops successfully validated transition states to `Passed (Green)` on compliance index **CIS Control 28638**.  
3. **Active Edge Blocking:** Validated that subsequent administrative logon requests were systematically rejected at the network socket interface layer.
